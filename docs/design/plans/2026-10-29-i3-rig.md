# I3: the interop rig — Implementation Plan (as built)

**Goal:** every party of a Mokuro library as its own real process — a testing build of
Bunko, cloudsim (Drive, OneDrive, MEGA), rclone's WebDAV server, a fake OCR processor
and Mokuro Reader built with `--mode interop` — driven through the reader's own UI code
by Playwright, on every Bunko PR and every reader PR, with no real cloud anywhere.

**Spec:** `docs/design/interop-testing.md` §7.1 (suites, scenarios S1–S9, the as-built
notes), §6 (cloudsim), §9 (CI wiring), §10 (I3 row), §11 (open items).

**Repos and branches:**
- Bunko: `interop/i3-rig` (from `0.8/remote-storage` with the 0.8 topics merged).
- Reader: `feat/interop-i3` (from `feat/cloud-bunko` with the interop contract and
  cloudsim work), which carries the rig driver.

## Shared contract

| Element | Shape |
|---|---|
| `interop/reader.ref` | One 40-hex SHA of a **pushed** Mokuro Reader commit, a newline, nothing else. Bumped only by a Bunko PR, whose rig run must pass against that commit. |
| Nightly pre-releases | `nightly` (from `main`) and `nightly-0.8` (from `0.8/remote-storage`): `mokuro-bunko-testing-x86_64-linux`, `bunko-cloudsim-x86_64-linux`, `nightly.json` = `{bunko_sha, branch, version, built_at}`. No signed `release.json`, so the updater never takes one. |
| Reader variable `BUNKO_REF` | A Bunko branch, default `0.8/remote-storage`. `0.8/remote-storage` → `nightly-0.8`, `main` → `nightly`, anything else builds from source. Flipped to `main` once 0.8 merges there. |
| `__mokuroInteropConfig` v1 | Set by the rig before any page script: `{v: 1, bases?, tokens?, gapiShim?}`. Read once by `cloud-test-hooks.ts`, interop builds only. |
| `__mokuroInterop` v1 | The reader's driver (`src/lib/interop/rig-driver.ts`): `apiVersion`, `capabilities`, C6's twenty connect/sync/library/open/rename/delete/edit/publish and state calls, and the six the suites added before any pin (`showSeries`, `pendingOcr`, `idle`, `importVolume`, `backupVolume`, `settleSeriesWrites`; interop-testing.md "The driver API v1"), each through the stores and functions the UI calls. Beside it, `__mokuroCloudTestHooks.setCloudTestToken` hands over a re-minted token. The fixtures check every v1 method before a spec runs; a method added after the first `reader.ref` comes with `apiVersion` 2. A production build folds both away (`scripts/check-no-test-hooks.mjs`). |
| `interop/pending-reader-caps.txt` | Capabilities whose specs are skipped (and reported) instead of failed. Empty when I3 is done. |
| Spec environment | `READER_URL`, `BUNKO_URL`, `CLOUDSIM_URL`, `CLOUDSIM_PREAUTH_URL`, `RCLONE_URL`, `RIG_PROVIDER`, `RIG_ACCOUNTS`, `RIG_WORKDIR`, `RIG_FAKEPROC_HOLD`, plus `RIG_CONTEXT` and `RIG_CONTROL_URL`. |
| Results | `target/interop/rig/<suite>-<provider>.json` = `{suite, provider, bunko_sha, reader_sha, passed, failed, skipped: [{spec, capability}], duration_ms, pending_caps, refused_hosts, stubbed_urls}`, Playwright JUnit XML beside it, every party's log under `logs/<suite>-<provider>/`. |

## Tasks

Each task names its spec id (the C6 cluster of the 0.8 crossplay program) and what
"done" meant. All are built; the interop-testing.md "As built" notes record what each
turned out to need.

### Bunko

- **B8.1 (C6-B5) cloudsim `/_sim/node` and `/_sim/tree`.** Path seeding cannot express
  two folders of one name or show the trash. `POST /_sim/node` makes a node beside any
  of the same name (OneDrive: 409 `nameAlreadyExists`, as Graph), dated as asked;
  `GET /_sim/tree` lists every node with `trashed` (and later `explicitly_trashed`).
  Done: `crates/bunko-cloudsim/tests/control.rs` covers same-named folders on Drive and
  MEGA, dates, the trash and the OneDrive 409.
- **B8.2 (C6-B6) `processor-fake`.** A hidden `mokuro-bunko processor-fake` in the
  `testing` build: a remote processor over `FakePipeline`, with `--hold-file` (a rename
  during OCR, deterministic), `--engine-revision` and `--page-text`. Done: a held volume
  completes once the file exists; the sidecar carries Bunko's provenance stamp.
- **B8.3 (C6-B7) runner core.** `cargo xtask interop rig <suites> --provider …`: suite
  and provider expansion, the testing-build check, servers on a local library or on a
  cloud, rclone pinned by sha256 and size, results JSON, the `cloud` suite in Rust.
- **B8.4 (C6-B8) reader build and harness.** `--reader-dir` or the commit in
  `interop/reader.ref`; `npm ci` and `vite build --mode interop`, cached; `vite
  preview` on a port the rig picks; Playwright fixtures that keep every request on this
  machine, set `__mokuroInteropConfig`, gate capabilities against
  `pending-reader-caps.txt` and fail a spec on cloudsim violations. Without a
  `reader.ref` and without `--reader-dir` the rig stops, naming both. Done: `npm run
  selftest` in `interop/` (gate, route, resolver, request recording) and the smoke specs.
- **B8.5 (C6-B9) suites `dav`, `api`, `bridge`, `direct`, `shared`.** The §7.1 checks,
  each spec making its own accounts. Done: every suite green on every provider it runs
  on, no cloudsim violation, no refused host.
- **B8.6 (C6-B10) scenarios S1–S9.** The program's cross-party cases, one spec each,
  enabled as its pair of fixes landed (table below). Done: each scenario failed with
  its fix reverted (the detection checks in the as-built notes) and passes with it.
- **B8.7 (C6-B11) nightly pre-releases.** `.github/workflows/interop-nightly.yml`.
- **B8.8 (C6-B12) the rig on Bunko CI.** `.github/workflows/interop.yml`: `catalog-perf`
  stays; pushes to `main` and `0.8/remote-storage`, and every PR. `rig-build` reads
  `interop/reader.ref` (failing with a message naming the file while it is absent),
  builds the testing server, cloudsim and xtask, checks out and builds the pinned
  reader as the rig does, runs the harness self-test and uploads one tar (binaries,
  reader with its install). `rig` is a `fail-fast: false` matrix, one leg per row:

  | Leg | Command (`cargo xtask interop rig …`) |
  |---|---|
  | local | `dav,api --provider local` |
  | google, microsoft, mega, rclone | `bridge,direct,shared --provider <p>` |
  | cloud | `cloud --provider all` |

  each with `--bin`, `--cloudsim-bin` and `--reader-dir` naming what `rig-build` made,
  and `target/interop/rig/` uploaded on every run.
- **B8.9 (C6-B13) docs.** This plan; interop-testing.md §6, §7.1, §9, §10, §11; the
  CHANGELOG line.

### Reader

- **R10.1 (C6-R8) hooks and driver.** `__mokuroInteropConfig` read by
  `cloud-test-hooks.ts` (bases, a Google or OneDrive token, the gapi REST shim in place
  of apis.google.com), and `rig-driver.ts` (`__mokuroInterop` v1), loaded by dynamic
  import under `CLOUD_TEST_HOOKS` only.
- **R10.2 (C6-R9) the rig on reader CI.** `.github/workflows/interop.yml` job `rig`:
  PRs to `main`, `develop` and `feat/cloud-bunko`, a nightly schedule (develop and
  feat/cloud-bunko) and workflow_dispatch. A `rig-refs` job lists the commits that have
  `src/lib/interop/rig-driver.ts`; with none (a develop PR from before the driver) the
  rig shows as skipped. Bunko comes from the nightly `BUNKO_REF` maps to (checked out at
  `nightly.json`'s `bunko_sha`, so the runner and specs match the binaries), else from
  source; then `cargo xtask interop rig all --provider all --reader-dir <the PR's
  reader>`, results uploaded on every run.

## Done when

The matrix is green on both repos' CI, `/_sim/violations` is empty after every spec,
`interop/pending-reader-caps.txt` lists nothing, and `interop/reader.ref` names the
pushed reader head.

## Owner actions

- Push the reader branch, then commit its head SHA as `interop/reader.ref` (nothing
  before that can fetch it: the Bunko `rig-build` job fails, naming the file, until it
  exists). A local run passes `--reader-dir` instead.
- Set the reader repository variable `BUNKO_REF` (default `0.8/remote-storage`; `main`
  once 0.8 is merged there).
- The D26 check by hand on live test accounts: a reader's Google logout revokes
  project-wide and signs Bunko out. cloudsim cannot show it; the rig's `dav/auth` covers
  only Bunko's own token revocation.
